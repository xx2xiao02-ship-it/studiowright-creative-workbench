请求准备

调用地址是 http://127.0.0.1:18922。远程连接时需保持算力中心的端口转发。请求带 Authorization: Bearer <算力中心密钥>；JSON 用 application/json，文件原始字节用 application/octet-stream。

提交对话、识图或生成前，用 Idempotency-Key 传入并保存一个 UUID。超时或返回 unknown 时用原编号查询，不能换新编号重发。

GET/health统一 API 存活检查，不需要密钥；只说明 18922 端口可访问。
GET/api/health带密钥读取 API v1、部署信息和请求策略。
GET/api/snapshot读取 flow_models、tasks、real_accounts 和可用状态；提交前重新读取。

状态处理：200/201 表示查询或创建成功，202 表示已排队，400/401/403/404/409 表示请求或状态问题，502/503 表示上游暂时不可用。连接超时、502、503 或 unknown 都要保留原编号查询，不能重复生成。

Python 公共准备 · 先设置 STUDIOWRIGHT_API_KEY
import json, os
from pathlib import Path
from uuid import uuid4
from urllib.request import Request, build_opener, ProxyHandler

BASE = "http://127.0.0.1:18922"
AUTH = {"Authorization": "Bearer " + os.environ["STUDIOWRIGHT_API_KEY"]}
HTTP = build_opener(ProxyHandler({}))

def call(path, payload=None, request_id=None, *, file=None):
    headers = dict(AUTH)
    body = None
    if request_id:
        headers["Idempotency-Key"] = request_id
    if file is not None:
        headers["Content-Type"] = "application/octet-stream"
        body = Path(file).read_bytes()
    elif payload is not None:
        headers["Content-Type"] = "application/json"
        body = json.dumps(payload).encode("utf-8")
    with HTTP.open(Request(BASE + path, data=body, headers=headers), timeout=180) as res:
        return json.load(res)

Gemini · 对话与推理

POST/api/conversations传 title，返回对话 id。
POST/api/real-pool/chat传 conversation_id、account: "auto"、prompt，返回 request_id 和 status。

新文字对话默认使用 gemini-4-hydrogen-medium。可以传 effort 调整思考等级，也可通过 model 显式选择 gemini-4-neon 或 gemini-4-carbon。Carbon 支持 low、medium、high，省略档位时用中档。旧调用传 gemini-3.8-flash 开新对话时，按 HY 优先处理。

自动选账号的 HY 首轮在发送前找不到可用主模型账号时，才用 3.8 Flash 保底。可传 fallback_model: false 关闭。结果里的 requested_model、model 和 fallback.used 分别显示主模型、实际模型和是否保底。

续聊沿用实际绑定的账号和模型系列。已开始调用后的错误按原模型规则处理，结果未知时查原请求编号。两个模型池都不可用时，提交前返回 HTTP 409。

Google 公告将于 2026 年 11 月 30 日移除 3.8 Flash。保底在官方仍提供该模型时可用。

}, rid)
print(queued["request_id"], queued["model"], queued.get("fallback"))
# 轮询 call(f"/api/real-pool/requests/{rid}") 查询最终型号和回复。

Gemini · 模型使用推荐

算力中心默认使用 HY（Gemini 4 Hydrogen）中档。高频、可快速核对的任务先试低档，综合理解用中档，关键判断和返工成本高的任务用 Neon 高档。最高档（xhigh）只用于高档做不稳、且值得复核的少数任务。

算力中心选型与计费

算力中心 API 可显式选择 HY、Neon 或 Carbon 的文字模型。实际档位取决于账号已开通的选项。可使用 gemini-4-hydrogen-low、gemini-4-neon-high 或 gemini-4-carbon-high 等完整模型 ID。同时传 effort 时须与型号一致。首轮省略模型和档位使用 HY 中档。没有已开通 HY 低档的账号时，可选择 HY 中档。切换模型系列要新建对话。

3.8 Flash 低档适合过渡期的轻量任务。Antigravity 计划于 2026 年 11 月 30 日移除 3.8 Flash。算力中心新对话的旧 Flash 型号请求会优先走同档 HY，Flash 可用时承担发送前保底。单独选择 Flash 可在官方 CLI 仍提供该型号时操作。

Carbon 可在「自定义对话」和文字 API 中选择。低档用于已有明确材料的快速复核，中档用于多步骤推理，高档用于长材料核验和反复失败的疑难任务。省略 Carbon 的档位时使用中档。3.5 Flash-Lite 可通过另接 Google Gemini API 使用。

识图与视频抽帧使用同一个识别接口，支持 effort 和 fallback_model。需要准确跟随指定档位时，可关闭 Flash 保底。Neon 和 Carbon 的文字请求可传整理好的识别结果、镜头笔记或转写。现有识图接口不接收 model。新闻搜索先由外部工具获取原文，再交给算力中心整理。

POST/api/real-pool/image-analysis传 account: "auto"、prompt、attachments（上传回执数组），请求头沿用上传路径中的编号。返回 request_id、status 和 conversation_id。

识图默认使用 HY 中档，自动选账号时沿用发送前的 Flash 保底规则。通过 fallback_model: false 限制为只用 HY。

可传 1～4 张 JPG、PNG、WebP，单张最多 8 MiB、合计 16 MiB、单张不超过 2400 万像素。只校验时用 POST /api/real-pool/image-analysis-validate，参数相同，返回 valid、submitted: false 和 image_count。

复制识图请求 · 默认只校验
files = [Path("产品.png"), Path("场景.jpg")]
rid = str(uuid4())
print("请求编号:", rid, flush=True)
attachments = [
    call(f"/api/real-pool/uploads/{rid}/{i}/{f.suffix.lower().lstrip('.')}", file=f)
    for i, f in enumerate(files)
]
payload = {"account": "auto", "prompt": "请按顺序分别描述图片。", "attachments": attachments}
print(call("/api/real-pool/image-analysis-validate", payload, rid))
# 正式识图：print(call("/api/real-pool/image-analysis", payload, rid))

Flow · 生成图片或视频

POST/api/real-pool/flow传 kind、confirm: true 和 params。返回 request_id、status、task_id；submitted 表示已排队。

Flow 确认接收视频后释放派发名额，其他账号可以继续上传和提交。同账号依次处理自己的任务，已提交视频由算力中心跟进并下载。提交后保留原 task_id，可继续提交新请求并轮询前一条的结果。

图片在 params 里填写 prompt、model、aspect、count；视频额外填写 resolution、duration。模型 ID 从快照取。时长按模型区分：Omni 1.1 Flash 为 4/6/8/10 秒，Omni 1.2 Flash 为 3～15 秒连续可调；画面比例 16:9 或 9:16。账号和项目由算力中心安排；积分按 Flow 实际报价计费，平台不设单笔上限。单图或单视频在请求顶层传 "auto_retry": false 后只尝试一次。

复制纯文字生成请求 · 实际提交
rid = str(uuid4())
print("请求编号:", rid, flush=True)
payload = {
    "kind": "image",  # 生视频时改为 video，并补上 resolution 和 duration；首尾帧参考见下方"带参考素材"
    "confirm": True,
    "params": {"prompt": "一张清晨海边的照片", "model": "填写快照中的模型 ID",
               "aspect": "16:9", "count": 1}
}
print(call("/api/real-pool/flow", payload, rid))

带参考素材

POST/api/real-pool/flow-references/auto/{素材 UUID}/{扩展名}逐个上传文件原始字节，返回 reference_id。上传、校验和提交使用同一个 Idempotency-Key，不填账号或项目。
模式在 params 中添加
图生图mode: "image-to-image" 和 reference_ids（图片编号数组）
Omni 首帧或首尾帧mode: "frames"、start_reference_id，可选 end_reference_id（图片编号）
Omni 混合参考model: "omni-flash-1.1"、mode: "ingredients" 和 reference_ids（图片、MP4 编号数组）

参考文件支持 JPG、PNG、WebP 和上述模式允许的 MP4，不接收独立音频。单文件最多 8 MiB、合计 64 MiB，编号 24 小时有效。单图或单视频由平台统一启用换号重试，最多换 3 个账号；重试行为不受调用方控制。图片只在确认未发送时重试；视频重试沿用原任务的时长与清晰度。结果不明不重发。查询和下载始终用原任务编号。只校验时发送 POST /api/real-pool/flow-validate 并设 confirm: false，返回 valid、submitted: false 和 reference_count。

复制参考素材请求 · 默认只校验
rid = str(uuid4())
print("请求编号:", rid, flush=True)
file = Path("首帧.png")
ext = file.suffix.lower().lstrip(".")
ref = call(f"/api/real-pool/flow-references/auto/{uuid4()}/{ext}",
           request_id=rid, file=file)
payload = {
    "kind": "video", "confirm": False,
    "params": {"prompt": "镜头平稳前推", "model": "omni-flash-1.2", "aspect": "16:9",
               "count": 1, "resolution": "720p", "duration": 8,
               "mode": "frames", "start_reference_id": ref["reference_id"]}
}
print(call("/api/real-pool/flow-validate", payload, rid))
# 正式提交：将 confirm 改成 True，再调用 /api/real-pool/flow。

音乐生成与音频

在 18922 端口提交音乐生成任务、查询进度，并从素材库筛选和下载音频。沿用算力中心密钥。

POST/api/music/jobs返回202和job。request_id 必填 UUID，保存后用于查询；Idempotency-Key 如传入必须一致。
GET/api/music/jobs/{request_id}只查询原任务，不重新生成；不存在返回404。

prompt：1～2000字。model：lyria-fast（默认，Lyria 3.5 Fast）、lyria（Lyria 3.5）、lyria-pro（Lyria 3 Pro）、lyria-pro-fast（Lyria 3 Pro Fast）。时长写进提示词，不保证精确时长。

tags：可选字符串数组，最多30个，每个1～80字；style_id：可选1～256字非空字符串。手动标签和画风 ID 原样保存，不传照常生成入库。auto_tags 从提示词自动提取，表示生成要求，不代表音频分析；未识别内容不猜测，不调用额外模型，不覆盖手动标签。

状态：generating生成中、ingesting入库中、recovering恢复原任务、completed已取得结果、unknown待核对。同编号同内容只生成一次，修改标签或画风 ID 也算不同内容，返回400。断线、刷新和重启后只查询原编号，不自动重发。

result.music_tags 和 clips[].music_tags 按 music_style（音乐风格）、music_mood（情绪）、music_instrument（乐器）、music_use（用途）、music_voice（人声）分类；auto_tags 平铺列表保留兼容。素材库可用同名参数叠加筛选，例如 kind=audio&music_instrument=钢琴&music_mood=舒缓。result.clips：音频/WAV地址和标签；result.library：入库回执，含asset_id、path、kind、ok。result.ingested 是文件数。completed若带ingest_error或ingested=0，表示音乐已有结果但入库未完成，不能为了入库重复生成。

GET /api/library?kind=audio&tag=钢琴 可筛选标签，叠加style_id精确筛选画风ID；参数使用URL编码。GET /api/library/{asset_id} 查详情，GET /api/library/{asset_id}/file 带同一密钥下载。优先使用入库路径，外部音频地址可能过期。

统一 API 不开放音乐账号管理、就绪操作、同步generate或jobs/latest。手动标签和画风 ID 保存在原任务，重启恢复不会丢失。

素材列表可用 audio_category 筛选音乐、音效或其他，用 duration_min、duration_max 按实际秒数筛选，包含边界，可只填写一端。可叠加标签与画风 ID。

音频素材详情返回 duration（实际秒数，未读取时为 null）与 audio_category（music 音乐、sound_effect 音效、other 其他）。

音乐生成、查询与下载示例（沿用公共准备）
# 沿用上文的 call、BASE、AUTH、HTTP。
from urllib.parse import urlencode
import time
rid = str(uuid4())  # 保存此编号；网络中断后只查询它
job = call("/api/music/jobs", {
    "request_id": rid,
    "prompt": "轻快钢琴背景音乐，无人声，适合口播，约30秒",
    "model": "lyria-fast",
    "tags": ["项目A", "片头备选"],
    "style_id": "STYLE-001"
}, rid)["job"]
for _ in range(180):
    if job["status"] in ("completed", "unknown"):
        break
    time.sleep(5)
    job = call("/api/music/jobs/" + rid)["job"]
print(rid, job)
# unknown 或仍在执行：保留 rid，稍后 GET；不要换编号重新生成。
if job["status"] == "completed":
    for i, item in enumerate(job["result"].get("library", [])):
        if item.get("ok") and item.get("path"):
            # path 为同一统一 API 的素材下载路径；格式见素材详情 mime。
            with HTTP.open(Request(BASE + item["path"], headers=AUTH), timeout=180) as res:
                with open(f"{rid}-{i}.audio", "xb") as output:
                    while chunk := res.read(65536):
                        output.write(chunk)
query = urlencode({"kind": "audio", "audio_category": "music",
                   "duration_min": 30, "duration_max": 65, "tag": "钢琴", "style_id": "STYLE-001"})
print(call("/api/library?" + query))

结果与下载

GET/api/real-pool/requests/{请求编号}查询文字或识图。status 为 completed 时，response 是回复；处理中继续查，失败或未知时读 note。
GET/api/real-pool/flow-requests/{请求编号}查询提交记录。task_id 始终是原任务号，task 是最新执行结果。
GET/api/tasks/{原任务编号}直接查询最新状态和下载路径，换号重试后仍用原任务号。
POST/api/tasks/{原任务编号}/retry确认单图失败后，沿用该次的账号、项目和参数，继续使用原任务号。请求体为 {"expected_ordinal":0,"confirm_generation":true}。

expected_ordinal 填原任务里最近一次已核对尝试的 ordinal，首次为 0。同一个尝试序号重复提交只补跑一次。收到 202 后继续查原任务号。任务结果待核对或已变化时，接口返回 409。

GET/api/tasks/{任务编号}/files/{序号}下载生成文件。使用任务的 downloads[].path，带同一密钥，返回文件字节。
复制查询与下载
# rid 为发送时保存的编号。查文字或识图：
# print(call("/api/real-pool/requests/" + rid))
record = call("/api/real-pool/flow-requests/" + rid)
print(record)
if record.get("task_id"):
    task = call("/api/tasks/" + record["task_id"])
    if task:
        print(task["status"])
        for item in task["downloads"]:
            with HTTP.open(Request(BASE + item["path"], headers=AUTH), timeout=180) as res:
                with open(Path(item["name"]).name, "xb") as output:
                    while chunk := res.read(65536):
                        output.write(chunk)

已入库素材：GET /api/library?page=1&limit=24 查列表，GET /api/library/{素材ID} 查详情，GET /api/library/{素材ID}/file 下载原文件。

错误通常返回 {"error":"原因"}。401 检查密钥，400 检查请求参数，404 核对路径或编号，409 先查询原任务。GET /health 检查 18922 API 是否可访问，无需密钥。
